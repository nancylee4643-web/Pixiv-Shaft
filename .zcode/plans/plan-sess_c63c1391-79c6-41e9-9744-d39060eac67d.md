# 同义词扩大搜索（插画标签搜索多路合并，支持多标签）

## 背景

项目已有完整的同义词词典体系（`synonym_target_table`/`synonym_tag_table` + `SynonymMatcher` 匹配引擎 + 总开关 `isSynonymDictEnabled`，默认关），但尚未接入搜索。本次在插画搜索链路接入：**标签搜索（单词或多标签 AND）时自动按词典展开同义词，多路并发请求，结果合并去重显示**。

关键结论（已调研确认）：
- Pixiv 搜索多词是 AND 语义、无 OR 语法。"扩大"（保持 AND 的并集扩展）= 对每个词的同义词组做**笛卡尔积**，逐组合发独立请求再客户端合并。例：搜 "A B"，A 有同义词 A1、B 有同义词 B1 → lanes = "A B" / "A1 B" / "A B1" / "A1 B1"。
- 组合数会爆炸（每词 2 个同义词 × 2 词 = 9 路），需按**替换数升序**（原始查询 → 单替换 → 双替换…）优先枚举并设总路上限 `MAX_LANES = 9`（两词各 ≤2 同义词可全覆盖；更多词/同义词被按优先级截断，原始终终是 lane 0）。
- 搜索链路收口在 `SearchIllustFeedSource.load()`（`SearchIllustFeedFragment.kt`）；`FeedViewModel` 已按 `identity`（= illust.id）全表去重，跨路重复天然被去掉。
- 每路必须是独立 `SearchIllustRepo` 实例（借号会话 `nana7miSession`、`FilterMapper` 均为实例级状态）；并发先例：`NovelTextFeed.fetchNovelRelated`（`async/awaitAll`）。

## 改动清单

### 1. `SynonymMatcher` 新增变体组纯函数

文件：`app/src/main/java/ceui/pixiv/db/synonym/SynonymMatcher.kt`

```kotlin
/**
 * 搜索扩展：把搜索关键词按空白（含全角空格）拆词，对每个词在词典中找变体。
 * 单个词的命中规则 = 归一化(trim+lowercase)后等于某目标名或其任一同义词名；
 * 命中 → 该词变体组 = [原词, 目标名, 该目标全部同义词...]（跨命中目标合并，
 *   按归一化去重保留首原形，剔除与原词相同者）；
 * 未命中 → 组 = [原词]。
 * @return 每个词一个变体组，顺序与拆词结果一致。备注(remark)不参与（与既有匹配规则一致）。
 */
fun keywordVariantGroups(keyword: String, dictionary: List<TargetWithSynonyms>): List<List<String>>
```

复用现有 `normalize()`；变体保留词典原大小写（仅比较归一）。空白关键词 → 返回空列表（调用方不扩展）。

### 2. 新文件 `SynonymSearchExpansion`（组合与游标编解码）

新文件：`app/src/main/java/ceui/pixiv/ui/search/SynonymSearchExpansion.kt`（internal object，纯逻辑便于单测）

```kotlin
internal object SynonymSearchExpansion {
    const val MAX_LANES = 9
    const val CURSOR_PREFIX = "synonym_lanes:"

    /** 变体组 → lane 查询串列表（每 lane = 各组取一词、空格连接）。
     *  笛卡尔积按替换数升序、同替换数按组序稳定排列，截断到 maxLanes；
     *  lane 0 恒为全原词的原始查询；任意组只有原词时结果 = [原始查询]。 */
    fun buildLaneQueries(groups: List<List<String>>, maxLanes: Int = MAX_LANES): List<String>

    /** 多路 next_url 编码进一个 String 游标（"\n" 连接，null/空白=该路到底）；
     *  全部到底 → null。URL 不含换行，编码安全。 */
    fun encodeCursor(laneUrls: List<String?>): String?

    /** 无前缀 → null（调用方走单路裸 URL 路径）；有前缀 → 各路 url 列表（""=到底）。 */
    fun decodeCursor(cursor: String): List<String>?
}
```

### 3. `SearchIllustFeedSource` 多路合并

文件：`app/src/main/java/ceui/pixiv/ui/search/SearchIllustFeedFragment.kt`

**门控**（首页 `cursor == null` 时判定，全部满足才扩展；单词/多词查询均支持）：
- `Shaft.sSettings.isSynonymDictEnabled && Shaft.sSettings.isSynonymExpandSearchEnabled`
- `searchModel.searchType.value` 为标签档：`null` / `partial_match_for_tags` / `exact_match_for_tags`（`title_and_caption` 标题简介档不扩展）
- 关键词非空白、扩展 lanes > 1

**取词与组 lane**：`withContext(Dispatchers.IO)` + try-catch 兜底（对齐 `applySynonymMatching` 惯例）：
`AppDatabase.getAppDatabase(Shaft.getContext()).synonymDao().getAllWithSynonyms()` → `SynonymMatcher.keywordVariantGroups(keyword, dict)`；每个变体词过 `SearchRiskPolicy.shouldWithhold`（命中的变体从组内剔除；原词已由既有的整句 withhold 检查覆盖）→ `SynonymSearchExpansion.buildLaneQueries(groups)`。

**首页加载**（扩展激活，lanes = [原始查询] + 扩展查询）：
- 每代搜索新建 lane repos：`laneRepos = laneQueries.map { repoFactory() }`（lane 0 为主路）
- `coroutineScope { async }` 并发：每路 `update(searchModel, laneQuery)` + `initApi()`（starSize 后缀、sort 路由、借号等每路独立复用全套既有逻辑）
- 主路失败 → 异常上抛（走现有错误 UI/重试）；扩展路失败 → 捕获丢弃该路（**rethrow `CancellationException`**）
- 每路结果过自己 repo 的 `mapper().apply()`，`IllustFeedItem.raw` 建条目，按 lane 序（原始查询在前）拼接；跨路去重由 `FeedViewModel` 完成

**翻页**：游标带 `CURSOR_PREFIX` → `decodeCursor` 得各路 url，逐路 `repo.nextUrl = url; initNextApi()` 并发推进合并；主路错误上抛、扩展路错误丢路；lane 数与游标段数不匹配时防御性返回空终止页。全部路到底 → `nextCursor = null` 正常触底。**无前缀的裸 URL 游标 = 现有单路路径，未激活扩展时与现状完全一致（零回归）**。

**Toast**：扩展生效且首页成功后，`withContext(Dispatchers.Main)` + `Common.showToast(Shaft.getContext().getString(R.string.synonym_search_expand_toast, addedWords))`，addedWords = 全部新增变体词去重后 "、" 连接；source 实例记 `lastToastedKeyword`（按原始关键词去重，同词只提示一次）。
